# Issue #1449: provide a gong migration cli/app for single stage data file format to multiple stage data file format

## Situation

Following the implementation of:
- [#1446](https://github.com/fullstack-lang/gong/issues/1446): Multi-package `StageSet` data layer, topological ordering, and marshalling format (`stageSet.MarshallToString()`, `stageSet.ParseAstFile()`, `stageset.go`).
- [#1447](https://github.com/fullstack-lang/gong/issues/1447): `StageSetProbe` data editor with cross-package navigation trees, tables, and forms.
- [#1448](https://github.com/fullstack-lang/gong/issues/1448): Multi-stage class diagrams (`diagrams_set.go`), multi-package AST loading, and cross-package links in `lib/doc`.

All existing applications, DSM projects (`dsm/project`, `dsm/structure`, `dsm/process`, etc.), and libraries (`lib/*`) across the repository currently store their persisted domain data in the legacy **single-stage data file format** (typically `data/stage.go`):

```go
// file generated by gong
package main

import (
	"time"

	"github.com/fullstack-lang/gong/test/test2/go/models"
)

var (
	_ time.Time
	_ *models.Stage
)

func _(stage *models.Stage) {
	// Declarations of staged instances
	__A__000000_A1 := (&models.A{Name: `A1`}).Stage(stage)
	__B__000000_B1 := (&models.B{Name: `B1`}).Stage(stage)

	// Setup of values
	__A__000000_A1.Name = `A1`
	__A__000000_A1.NumberField = 42
	__A__000000_A1.Foo = 100
	__B__000000_B1.Name = `B1`

	// Setup of pointers
	__A__000000_A1.B = __B__000000_B1
}
```

The new **multiple stage data file format** (`stageset.go`) organizes declarations and associations around `StageSet`, utilizing synthetic imports (`__stage_0__`, `__stage_1__`, ...) and a structured 3-phase execution:

```go
// file generated by gong
package main

import (
	"slices"
	"time"

	__stage_0__ "github.com/fullstack-lang/gong/test/test2/go/models"
)

var (
	_ time.Time
	_ = slices.Index[[]int, int]

	_ *__stage_0__.Stage
)

func _(stageSet *__stage_0__.StageSet) {
	// Phase 1: Declarations (in topological order: leaves first)
	__stage_0__B__00000000_ := (&__stage_0__.B{Name: `B1`}).Stage(stageSet.Stage)
	__stage_0__A__00000000_ := (&__stage_0__.A{Name: `A1`}).Stage(stageSet.Stage)

	// Phase 2: Value Initializations
	__stage_0__B__00000000_.Name = `B1`
	__stage_0__A__00000000_.Name = `A1`
	__stage_0__A__00000000_.NumberField = 42
	__stage_0__A__00000000_.Foo = 100

	// Phase 3: Pointer Setups
	__stage_0__A__00000000_.B = __stage_0__B__00000000_
}
```

---

## Problem

As laid out in the multi-package roadmap ([#325](https://github.com/fullstack-lang/gong/issues/325)):
- After completing #1446, #1447, and #1448, the next milestone requires migrating all existing single-stage data files across all DSMs, libraries, and tests to the new `StageSet` format.
- There is currently no automated tool (neither a standalone CLI command nor an application subcommand) to convert existing `stage.go` files into `stageset.go` files.
- Manual conversion of dozens of files is error-prone, labor-intensive, and blocks:
  1. Deprecating single-stage level1stack and probe implementations.
  2. Eventually renaming `StageSet` to `Stage`.

---

## Solution

Provide a dual **CLI & App migration capability**:

### 1. Standalone CLI Tool: `gong migrate`
In `go/cmd/gong/cmd/migrate.go` and `go/golang/migrate.go` (mirroring `gong merge` and `gong scramble`):

```bash
# Migrate a single file to stageset.go
gong migrate data/stage.go -o data/stageset.go

# Migrate in-place (overwriting the input file or backup)
gong migrate data/stage.go -i

# Batch migrate all stage.go files in a directory tree
gong migrate ./...
```

#### CLI Migration Logic (AST-based, Zero Compilation Needed):
- Operates on the Go AST (`go/parser`, `go/ast`, `go/format`) without needing to compile the target package.
- **Header Transformation**:
  - Detects the models import path (e.g. `"github.com/.../models"`).
  - Emits the synthetic alias import: `__stage_0__ "<models_path>"`.
  - Injects dummy imports: `"slices"`, `"time"`, `_ *__stage_0__.Stage`, `_ = slices.Index[[]int, int]`.
  - Rewrites function signature: `func _(stage *models.Stage)` $\rightarrow$ `func _(stageSet *__stage_0__.StageSet)`.
- **Identifier & Phase Rewriting**:
  - Maps legacy identifiers `__<Struct>__<Digits>_<Name>` to `__stage_0__<Struct>__<08d>_`.
  - Replaces `.Stage(stage)` with `.Stage(stageSet.Stage)`.
  - Segregates statements into:
    - **Phase 1: Declarations** (`:= (&__stage_0__.<Struct>{Name: ...}).Stage(...)`)
    - **Phase 2: Value Initializations** (`.<Field> = ...`)
    - **Phase 3: Pointer Setups** (`.<PtrField> = ...`, `append(...)`)
  - Formats output with `go/format`.

### 2. In-App Migration Subcommand: `<app> migrate`
In generated Gong applications (`go/golang/cmd/package_main_migrate.go`):

```bash
go run ./go/cmd/<app> migrate [data/stage.go] [-o data/stageset.go]
```

#### In-App Migration Logic (Semantic Runtime Round-Trip):
Leverages the compiled Go models and generated `StageSet`:
```go
stage := models.NewStage("")
if err := stage.ParseAstFile(inputFile, true); err != nil {
    log.Fatalf("failed to parse input stage: %v", err)
}
stageSet := models.NewStageSetFromStage(stage)
stageSet.MarshallFile(outputFile, "main")
```
- Guarantees 100% schema fidelity with the generated `MarshallToString` implementation.
